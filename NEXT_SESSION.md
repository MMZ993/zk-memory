## Important Notes

### Alembic workflow

```bash
# Check current revision
PYTHONPATH=src alembic current

# Apply pending migrations
PYTHONPATH=src alembic upgrade head

# Create a new migration after ORM changes
PYTHONPATH=src alembic revision --autogenerate -m "add_column_x"

# Downgrade one step
PYTHONPATH=src alembic downgrade -1

# Stamp an existing DB (already has tables, no alembic_version yet)
PYTHONPATH=src alembic stamp head
```

> FTS5 is SQLite-only. Future PostgreSQL migrations need a separate or conditional migration path for FTS5 → `tsvector` + GIN index.

### Seeding the DB for manual CLI testing

The integration test suite seeds 14 notes + 13 links via the running API. Use this to populate a local instance for CLI testing:

```bash
# 1. Start the local stack (API on :8000, Qdrant on :6333)
docker compose up -d

# 2. Confirm API is up
curl http://localhost:8000/api/health

# 3. Run ONLY the seed step (import fixtures + call seed_data manually)
source .venv/bin/activate
python - <<'EOF'
import httpx
import sys
sys.path.insert(0, "tests")
from integration.fixtures import seed_data
client = httpx.Client(base_url="http://localhost:8000")
seed_data(client)
print("Seeded 14 notes and 13 links.")
EOF

# 4. Build and test the CLI
cd cli && go build -o dist/memory . && cd ..
MEMORY_API_URL=http://localhost:8000 cli/dist/memory notes list --pretty
MEMORY_API_URL=http://localhost:8000 cli/dist/memory admin health --pretty
MEMORY_API_URL=http://localhost:8000 cli/dist/memory dump --output /tmp/vault --format obsidian
```

### Key design notes

- `notes tags remove <note-id> <tag-id>` takes tag UUID (not name)
- `admin reembed start` requires `--confirm` flag
- `relations update` uses `PUT` (not `PATCH`) — per API spec
- `dump` fetches outgoing links only (`direction=outgoing`) per note
- `dump` always fetches all notes for ID→title resolution even on incremental runs
- datetime from API is `"2026-03-13T10:00:00"` (no Z) — Python naive UTC isoformat
